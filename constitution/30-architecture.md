# Архитектура: слои, usecase-паттерн, данные (постоянные правила)

Здесь — вечные архитектурные правила, не зависящие от текущего состояния кода.

## Слои и границы зависимостей

| Слой       | Пакеты                                       | Ответственность                                                           |
|------------|----------------------------------------------|---------------------------------------------------------------------------|
| Domain     | `internal/model/<x>`                         | модели, DTO команд - без бизнес-сценариев                                 |
| Usecase    | `internal/usecase/<x>`                       | бизнес-сценарии; валидация, доменные ошибки, координация                  |
| Delivery   | `internal/handlers/<x>/<x>`, `internal/echo` | только transport mapping (регистрация ручек, DTO⇄HTTP); без бизнес-логики |
| Repository | `internal/repository/<x>`                    | адаптеры хранения: транзакции, блокировки, маппинг ошибок БД              |
| Apps       | `internal/app/<x>`                           | сборка приложения: конфиг → зависимости → wiring → серверы                |

## Usecase-паттерн

- Конструктор `NewXxx(deps...)`, где Xxx название структуры сервиса; возвращает указатель на структуру
- Зависимости и недетерминизм — явные параметры: хранилище, `admins map[string]struct{}`,
  `now func() time.Time`. Параметр не передаётся, если контракт метода его не требует
  (нет времени в контракте — нет `now`).

## Идентичность логики

- Вся логика идентична на стейдже и проде и во всех режимах работы — 
  если явно не оговорено обратное. Различаться могут только конфигурация и топология
  (число нод, шардов, реплик), но не поведение кода.

## Интерфейсы

- Интерфейс для инфраструктурной зависимости объявляет **потребитель** (пакет usecase),
  и **только пока реальной реализации нет** — он нужен, чтобы unit-тесты работали на fake.
- Когда реальная реализация (база) появляется — новые интерфейсы «на всякий случай»
  не заводятся: зависимость берётся конкретным типом. Интерфейс ради интерфейса — запрещён.
